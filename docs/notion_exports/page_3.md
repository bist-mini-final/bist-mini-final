### 4-1. LLM Direct Cell Refiner 개발
1차 Reader LLM이 검색된 청크만을 바탕으로 답변할 때 발생하는 스프레드시트의 특정 연도 수치 누락, 셀 좌표 오인용, 미세 수치 환각(Hallucination) 문제를 원천 차단하는 2차 정밀 교정 모듈을 개발했습니다.
sequenceDiagram
    autonumber
    actor User as 사용자 질의
    participant Reader as 1차 Reader LLM
    participant Refiner as AnswerRefinerModule
    participant DB as PostgreSQL (Metadata Index)
    participant LLM as Refiner LLM (gpt-5.6-luna)

    User->>Reader: "2024년 영업이익과 최근 추이는?"
    Reader->>Refiner: 1차 초안 답변 (AnswerDTO) 전달
    
    rect rgb(240, 248, 255)
        Note over Refiner: 1. 후보 셀 추출
        Refiner->>Refiner: LLM으로 'I16' 좌표 추출 ➔ H16, J16, K16, L16 추가
    end

    rect rgb(245, 255, 245)
        Note over Refiner,DB: 2. PostgreSQL 메타데이터 직접 조회 (Direct SQL)
        Refiner->>DB: fetch_cells_by_metadata(coords, workbook_hash)
        DB-->>Refiner: 실제 원장 셀값, 행/열 계층 헤더 반환 (1~2ms)
    end

    rect rgb(255, 250, 240)
        Note over Refiner,LLM: 3. 2차 팩트 기반 교정 추론
        Refiner->>LLM: 1차 답변 + DB 원장 팩트 전달
        LLM-->>Refiner: 수치 검증 및 YoY/QoQ 추이가 보강된 최종 답변 생성
    end

    Refiner-->>User: RefinedAnswerDTO (최종 교정 답변 + 참조 셀 목록 + 정제 요약)

## 5. BI 대시보드 구현
본 프로젝트에서는 대시보드의 각 섹션을 유기적으로 구성하기 위해 RAG 기반의 데이터 처리 파이프라인을 도입합니다.
우선 각 섹션별 목적에 부합하는 최적의 쿼리를 사전 정의한 뒤, 해당 쿼리를 통해 RAG 파이프라인을 실행하여 필요한 컨텍스트를 수집합니다. 수집된 방대한 컨텍스트는 LLM에 전달되며, 시스템이 요구하는 포맷에 맞춘 구조화된 출력(Structured Output) 형태로 가공됩니다. 최종적으로 LLM을 통해 정제된 데이터는 시각화 라이브러리와 연동되어, 사용자에게 직관적이고 시각적으로 우수한 대시보드 인터페이스로 제공될 예정입니다.
