## 프로젝트 목표

S&P Capital IQ Pro 형식의 재무 엑셀에서 기업·지표·기간·단위를 보존해 데이터를 적재하고, 자연어 질문에 수치와 원본 셀 근거를 함께 제공하는 AI 분석 플랫폼을 구현했습니다. 검색 자체뿐 아니라 데이터 관리, 재무 시각화, 기업 비교와 비동기 실행까지 연결하는 것을 프로젝트 범위로 삼았습니다.

## 3단계 MVP와 완성된 기능

| 단계 | 검증 경계 | 구현 결과 |
| --- | --- | --- |
| 1. 핵심 RAG | 엑셀 구조를 보존하고 질문에 필요한 셀을 찾을 수 있는가 | VLM 구조 감지, 셀 직렬화, Dense·키워드 검색, RRF, 근거 기반 답변 |
| 2. 통합 분석 | 데이터·분석·실행 기반을 하나로 연결할 수 있는가 | 데이터 소스 관리, 재무 BI, PostgreSQL 큐, DAG 실행과 상태 저장 |
| 3. 서비스화 | 사용자가 분석 결과를 확인하고 실행을 추적할 수 있는가 | 챗봇·자동 차트, 기업 비교, 플레이그라운드, 작업 관제, Kubernetes·KEDA 확장 |

수식 엔진을 새로 구현하는 대신 엑셀에 저장된 값과 표 구조를 우선 활용했습니다. 수식 재계산·의존 관계 해석이나 모든 엑셀 양식의 완전한 지원을 완료 기능으로 간주하지 않습니다.

## 핵심 설계 성과

- **입력 구조 보존**: 표·헤더·데이터 영역을 구분하고 셀 텍스트에 기업·시트·행 및 열 헤더를 함께 담았습니다.
- **검증 가능한 답변**: 검색 후보와 실제 답변 근거를 구분하고, 선택된 근거 ID를 서버에서 검증해 원본 셀 조회로 연결했습니다.
- **모듈 재사용**: 17개 기능 모듈에 공통 입력·설정·출력 검증을 적용하고 DAG 연결을 통해 적재와 질의 흐름을 구성했습니다.
- **실행 표준화**: 6종 워커와 공통 실행 계약을 두고, PostgreSQL 상태·Lease·Heartbeat와 KEDA 확장을 결합했습니다.
- **분석 서비스 분리**: BI와 기업 비교는 독립 도메인으로 유지하며 검증된 스냅샷을 공유하도록 구성했습니다.

모듈·API·DB 수치와 책임 경계는 [현재 구현 기준선](CURRENT_IMPLEMENTATION_BASELINE.md), 세부 설계는 [20개 청사진](README.md#상세-설계-문서)을 기준으로 확인합니다.

## 평가 결과를 읽는 방법

최종 발표·보고서의 대표 정확도는 **81.45%**로 통일합니다. 다만 이 수치를 기존 자동채점 JSON에서 재산출한 값으로 소개하지는 않습니다.

| 기록 | 기준과 해석 |
| --- | --- |
| 최종 발표·보고 정확도 **81.45%** | 최종 보고 기준으로 정리한 대표 수치. 문항별 최종 판정 내역이 아래 자동채점 원본에 모두 반영된 상태는 아님 |
| 2026-09-02 자동채점 **75.81% · 94/124** | 당시 `corrected-direct-rag-query` 실행의 저장된 자동채점 결과. 실행 이미지·질문 구성·채점 조건과 함께 원본 보존 |
| 이전 부분집합·재실행 결과 | 특정 조건의 회귀 점검 기록. 전체 평가나 별도 미사용 평가셋의 일반화 정확도로 대체하지 않음 |

수치를 인용할 때는 **평가셋·실행 시점·자동채점 또는 최종 판정 기준**을 함께 명시합니다. 최종 수치의 문항별 재현이 필요하면 별도 최종 판정표와 실행 원본의 매핑이 필요합니다. 과거 결과를 최신 수치에 맞춰 덮어쓰지 않습니다.

근거: [서버 평가 기록 목차](evaluation/README.md), [2차 직접 질의 자동평가 보고](evaluation/05_benchmark_results/corrected-direct-rag-query-report.md).

## 지원 범위와 남은 운영 과제

- **데이터 품질**: 값 캐시, 통화·배율·기간 및 헤더가 불완전하면 답변 품질에 영향을 줍니다. 숫자만 보지 않고 근거 셀을 함께 확인해야 합니다.
- **모델 의존성**: VLM·질문 분해·임베딩·답변 생성은 외부 모델 API를 사용하므로 호출 비용, 지연, 서비스 가용성과 데이터 전송 정책을 고려해야 합니다.
- **배포 경계**: 로컬 시연 구성과 공개 운영 구성은 다릅니다. 공개 운영에는 TLS, 인증 Secret 관리, 백업·복원, 자원 산정이 필요합니다.
- **검증 경계**: 다중 tenant 격리, 유효한 500 MiB 파일의 전체 적재, 워커 강제 종료를 포함한 모든 장애 상황을 검증 완료로 표기하지 않습니다. 실행별 검증 범위는 [서버 평가 요약](evaluation/10_summary.md)에 보존했습니다.
- **판단 책임**: 이 시스템은 재무 정보 조회·분석을 보조하며 회계 감사나 투자 판단의 정확성을 보장하지 않습니다.

후속 작업은 이 완료 기록을 지우지 않고 새 이슈·PR에서 범위와 검증 기준을 명시해 진행합니다.
