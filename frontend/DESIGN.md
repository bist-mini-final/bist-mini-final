# RAG Flow 프론트엔드 디자인 시스템

이 문서는 현재 `global.css`, `app.css`, `playground.css`, `bi.css`와 공용 React 컴포넌트에서 반복되는 규칙을 추출한 구현 계약이다. 새로운 브랜드를 제안하는 문서가 아니며, 기존 RAG Flow 화면과 BI 화면이 같은 시각 언어와 접근성 기준을 사용하도록 고정한다.

## 1. 분위기와 정체성

### 제품 성격

- RAG Flow는 복잡한 데이터 처리 과정을 밝고 차분한 작업 공간으로 보여주는 웹 애플리케이션이다.
- 주조색은 엑셀 및 재무 작업과 자연스럽게 연결되는 녹색이며, 흰색 표면과 옅은 녹회색 캔버스가 정보 밀도를 낮춰 보이게 한다.
- BI는 재무 전문가가 아닌 일반 사용자가 한 기업의 핵심 수치, 기간 변화, 근거 상태를 빠르게 이해하도록 돕는다.
- 장식보다 상태와 계층을 우선한다. 색상은 브랜드, 선택, 상태, 근거 구분처럼 의미가 있는 위치에서만 사용한다.
- 아이콘은 프로젝트가 이미 사용하는 `lucide-react`만 사용한다. 이모지, 임의 SVG, CSS 그림을 아이콘 대용으로 사용하지 않는다.

### 핵심 사용자와 사용 맥락

- 기본 사용자: 전문 재무 용어에 익숙하지 않은 한국어 사용자
- 키보드 사용자: 기업 탭, 기간, 카드 편집, 다이얼로그, 근거 확인을 포인터 없이 완료해야 한다.
- 저시력 및 확대 사용자: 200% 확대와 좁은 화면에서도 주요 수치와 상태가 잘리지 않아야 한다.
- 모션 민감 사용자: `prefers-reduced-motion`에서 이동과 상태 전환이 즉시 적용되어야 한다.
- 상황적 제약 사용자: 375px 모바일 화면에서도 주 콘텐츠에 가로 스크롤이 생기지 않아야 한다.

### 디자인 원칙

1. 수치보다 먼저 맥락을 제공한다. 기업, 기간, 갱신 상태, 단위를 가까이 배치한다.
2. 결측·모호·오류를 0으로 보이지 않는다. 텍스트 상태와 근거 확인 경로를 유지한다.
3. 한 카드에는 하나의 금액 단위만 사용하고, 금액과 비율을 같은 축에 섞지 않는다.
4. 편집 기능은 평상시의 읽기 흐름을 방해하지 않도록 명시적인 편집 모드 안에 둔다.
5. App Shell의 구조와 녹색 계열을 유지하며 BI만을 위해 전역 화면을 재설계하지 않는다.

### 색상 사용 규칙

- 녹색은 브랜드, 활성 선택, 정상 완료, 포커스에 사용한다.
- 주황·황색은 `partial`, `missing`, `ambiguous`, `invalid`처럼 확인이 필요한 상태에 사용하되 반드시 텍스트 라벨을 함께 제공한다.
- 빨강은 삭제·중단·복구가 필요한 위험 동작에만 사용한다.
- 단순 증가와 감소를 녹색과 빨강으로만 구분하지 않는다.
- 새 의미 색상이 필요하면 먼저 이 문서에 역할을 추가한 뒤 CSS 변수로 구현한다.
- `app.css`와 `playground.css`에 남은 원시 색상은 기존 화면의 현재 상태로 인정하되, BI 신규 코드에서 복사하지 않는다.

## 3. 한국어 UI 및 숫자 타이포그래피

### 글꼴

- UI: `--font-ui` = `Noto Sans KR`, `Apple SD Gothic Neo`, `Malgun Gothic`, 시스템 sans-serif
- 코드·식별자: `--font-code` = `JetBrains Mono`, `SFMono-Regular`, `Consolas`, `Liberation Mono`, `Noto Sans KR`, monospace
- 한 화면에서 UI와 코드 글꼴 외의 글꼴을 추가하지 않는다.

### 현재 사용 규모

| 역할 | 범위 | 용도 |
|---|---:|---|
| 페이지 표시 제목 | `1.9rem`~`3.55rem` | 홈·BI 페이지 제목 |
| 페이지/모달 제목 | `1rem`~`2.7rem` | 섹션, 다이얼로그 제목 |
| 카드 제목 | `0.76rem`~`0.95rem` | 카드·패널 제목 |
| 본문 | `0.72rem`~`0.9rem` | 설명, 도움말, 상태 메시지 |
| 메타데이터 | `0.6rem`~`0.72rem` | 단위, 기간, 보조 정보 |
| 핵심 수치 | `1.45rem`~`2rem` | BI 대표값 |

### 규칙

- 핵심 숫자는 `font-variant-numeric: tabular-nums`를 적용하고 단위는 가까운 위치에 한 번만 표시한다.
- 한국어 본문은 `line-height: 1.5` 이상을 유지한다.
- 제목은 음수 자간을 사용할 수 있지만 본문 가독성을 위해 본문 자간은 기본값에 가깝게 유지한다.
- 한국어 조사나 문장 종결이 한 글자만 다음 줄에 남지 않도록 의미 단위 래핑을 우선한다.
- `0.7rem` 미만 텍스트는 배지·보조 메타데이터에만 사용하고, 핵심 상태와 동작 설명에는 사용하지 않는다.
- 긴 기업명과 파일명은 `text-overflow: ellipsis`와 원문을 제공하는 `title` 또는 접근 가능한 이름을 함께 사용한다.

## 4. 간격, 콘텐츠 폭, 카드 그리드

### 간격 체계

현재 UI는 `0.25rem` 단위를 기반으로 다음 간격을 반복 사용한다.

| 단계 | 값 | 대표 용도 |
|---|---:|---|
| 1 | `0.25rem` | 배지 내부, 밀집 아이콘 간격 |
| 2 | `0.5rem` | 버튼·인라인 그룹 |
| 3 | `0.75rem` | 카드 내부 작은 그룹 |
| 4 | `1rem` | 카드 간격, 기본 패딩 |
| 5 | `1.25rem` | 넓은 카드·다이얼로그 패딩 |
| 6 | `1.5rem` | 섹션 분리 |
| 8 | `2rem` | 페이지 블록 간격 |
| 12 | `3rem` | 넓은 화면의 페이지 여백 |
| 16 | `4rem` | 페이지 하단·주요 구획 여백 |

브라우저 반응형 계산에 필요한 `clamp()`, `%`, `minmax()`, viewport 단위는 토큰으로 강제하지 않는다.

### 콘텐츠와 스크롤 소유권

- App Shell은 `100dvh`를 사용하고 `.product-page`가 기본 주 세로 스크롤을 소유한다.
- Playground는 자체 캔버스와 패널이 스크롤을 나눠 소유한다.
- BI는 `.product-page` 안에서 문서형 세로 흐름을 사용하며 카드 내부에 세로 스크롤을 만들지 않는다.
- BI 최대 콘텐츠 폭은 `--bi-page-max: 76rem`이다.
- 모바일 App Shell 메뉴가 표시되는 `900px` 이하에서는 BI 상단에 `4rem` 안전 영역을 유지한다.

### BI 그리드

| 화면 | 열 | 카드 규칙 |
|---|---:|---|
| `1280px` 이상 | 12열 | S=4, M=6, L=12 |
| `768px`~`1279px` | 8열 | S=4, M=4, L=8 |
| `767px` 이하 | 1열 | 모든 크기를 한 열에 배치 |

- 모든 grid track은 `minmax(0, 1fr)`를 사용해 긴 콘텐츠가 페이지 너비를 확장하지 않게 한다.
- 375px에서 주 콘텐츠의 가로 스크롤을 허용하지 않는다.
- 기업 탭처럼 본질적으로 가로 목록인 컨트롤만 자체 가로 스크롤을 소유할 수 있다.
- 카드 내부 차트는 부모 너비에 반응하고 `전체` 기간에서는 축 라벨을 솎아 표시한다.

## 5. 재사용 컴포넌트와 상태

### App Shell

- **구조**: 고정 높이 shell → 접기 가능한 sidebar → 주 스크롤 영역
- **상태**: expanded, collapsed, mobile closed, mobile open, active route, planned route
- **접근성**: `main`, `nav`, `aside`, `aria-current`, 메뉴 열기·닫기 이름을 제공한다.
- **레이아웃**: shell이 viewport를 소유하고, 주 화면별로 스크롤 책임을 명확히 나눈다.

### 버튼

- **변형**: primary, secondary, icon, destructive, disabled
- **상태**: default, hover, active, focus-visible, disabled, loading
- **간격**: 아이콘과 텍스트는 `0.35rem`~`0.5rem`; BI 터치 목표는 최소 `2.75rem`(44px)이다.
- **접근성**: 아이콘 단독 버튼에는 `aria-label`을 제공하고 disabled 이유는 인접한 가시 텍스트로 설명한다.

### 탭과 분할 선택

- **구조**: 스크롤 소유 컨테이너 → `tablist` → `tab`, 또는 버튼 그룹
- **상태**: default, hover, selected/pressed, focus-visible
- **접근성**: 기업 탭은 좌우 방향키로 초점을 이동하고 Enter·Space로 선택한다.
- **레이아웃**: 긴 탭 목록만 내부 가로 스크롤을 허용하며 페이지 폭은 늘리지 않는다.

### 카드 셸

- **구조**: 제목·설명 → 대표 수치 → 차트/요약 → 상태·단위·기간 → 근거/질문 동작
- **크기**: S, M, L
- **상태**: loading, ready, partial, missing, ambiguous, invalid, hidden, editing
- **접근성**: 상태는 색상과 텍스트를 함께 사용하고, 편집 메뉴는 포인터를 대체하는 방향·크기 조작을 제공한다.
- **레이아웃**: 카드 자체는 세로 스크롤을 소유하지 않는다.

### 상태 필과 메시지

- **변형**: ready, processing, partial, missing, ambiguous, invalid, failed
- **상태 표현**: 아이콘 + 짧은 한국어 라벨 + 필요 시 한 문장 설명
- **규칙**: `missing`, `ambiguous`, `invalid`, `not_meaningful`을 서로 다른 문구로 유지한다.
- **접근성**: 비동기 상태 변화는 향후 API 연결 시 적절한 live region으로 알린다.

### 다이얼로그

- **구조**: native `dialog` → eyebrow·제목·닫기 → 본문 → 선택적 footer actions
- **변형**: 카드 복구, evidence, 초기화 확인, 설정, 스프레드시트 결과
- **상태**: open, empty, populated, confirmation, destructive confirmation
- **접근성**: `showModal()`, 명시적 제목 연결, Escape 취소, 키보드 포커스 순서를 사용한다.
- **레이아웃**: 모바일에서 내용량이 많은 다이얼로그는 전체 화면으로 전환할 수 있다.

### 차트 표면

- **구조**: 접근 가능한 제목 → 차트 → 범례 → 툴팁 → 동일 데이터의 읽기 가능한 요약
- **변형**: 단일 막대, 그룹 막대, 0선 막대, 막대+선, 누적 막대
- **상태**: loading, ready, partial, missing, ambiguous, invalid
- **접근성**: 색상만으로 시리즈를 구분하지 않고, 키보드와 화면 읽기 도구가 기간·값·단위·근거를 확인할 대체 경로를 제공한다.
- **레이아웃**: S에서는 렌더링하지 않고 M/L에서만 부모 너비에 맞춰 렌더링한다.

### BI 구현 라이브러리

- **차트**: `recharts@3.10.1`. React 18 호환 범위와 자체 TypeScript 선언을 확인했으며, 막대·선·누적 막대와 반응형 컨테이너를 공통 차트 표면 안에서 사용한다.
- **배치 편집**: `react-grid-layout@2.2.4`. React 18 호환 범위와 자체 TypeScript 선언을 확인했으며, 편집 모드의 전용 핸들에서만 포인터 drag·resize를 허용한다.
- 두 라이브러리는 BI 화면 안에서만 사용한다. 카드 메뉴의 순서·크기 변경은 포인터 조작과 동등한 키보드 대체 경로로 유지한다.

### 드래그·리사이즈 핸들

- **구조**: 편집 모드에서만 노출되는 header drag handle과 corner resize handle
- **상태**: idle, hover, focus-visible, dragging/resizing, disabled
- **접근성**: 카드 메뉴의 위·아래·왼쪽·오른쪽·S/M/L 조작을 항상 동등한 대체 경로로 유지한다.
- **레이아웃**: `768px` 미만에서는 포인터 resize handle을 숨긴다.

## 6. 모션과 상호작용

### 현재 타이밍 체계

| 역할 | 범위 | 사용처 |
|---|---:|---|
| 즉시 피드백 | `140`~`160ms` | hover, 버튼, 포커스 보조 변화 |
| 표면 전환 | `180`~`200ms` | 카드, 선택, 테두리, 그림자 |
| 패널 이동 | `220`~`260ms` | sidebar, palette, overlay panel |
| 로딩 회전 | `700ms linear` | 라우트 로딩 |

- 이동은 `cubic-bezier(0.16, 1, 0.3, 1)`, 색상은 `ease` 또는 `ease-out`을 기본으로 한다.
- 모션은 탭 활성, 패널 개폐, 카드 이동, 작업 상태처럼 의미 있는 변화에만 사용한다.
- 위치 이동은 `transform`, 시각 전환은 `opacity`와 색상 속성을 사용한다. 레이아웃 속성을 애니메이션하지 않는다.
- drag·resize 중에는 관련 transition을 끄고 포인터와 표면이 직접 반응하도록 한다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 transition을 `0.01ms`로 줄이고 즉시 상태를 반영한다.

## 7. 카드 표면, 테두리, 그림자

### 전략: 얕은 혼합형

기본 깊이는 테두리와 약한 그림자를 함께 사용한다. 브랜드 작업 공간은 부드럽게 보여야 하지만, 유리 효과나 강한 그림자가 데이터보다 앞서면 안 된다.

| 단계 | 구현 | 사용처 |
|---|---|---|
| 캔버스 | 녹회색 또는 옅은 radial gradient | 페이지와 작업 공간 |
| 기본 표면 | `--surface` + `1px --border` | 카드, 도구 영역, 버튼 |
| 카드 부양 | `--shadow-card` | 카드, 작은 floating control |
| floating 표면 | `--shadow-float` 또는 BI dialog shadow | 패널, 다이얼로그, popover |
| 선택 강조 | 브랜드 테두리·outline | 활성 탭, 편집 카드, 선택 노드 |

- 카드 radius는 `--radius-md` 또는 `--radius-lg`, 작은 버튼과 아이콘은 `--radius-sm`을 사용한다.
- pill은 상태·배지·짧은 메타데이터에만 사용한다.
- backdrop blur는 overlay나 실제 floating surface에만 사용하며 일반 카드에는 사용하지 않는다.
- BI 차트는 카드 내부의 한 단계 낮은 표면에 배치하고 별도의 강한 그림자를 추가하지 않는다.

## 8. 접근성 제약과 디자인 부채

### 필수 제약

- 목표는 WCAG 2.2 AA다. 본문 대비는 4.5:1, 큰 텍스트와 UI 경계는 3:1 이상을 목표로 한다.
- 모든 상호작용 요소에는 명확한 `focus-visible` 표시가 있어야 한다.
- BI 버튼과 편집 조작의 모바일 터치 목표는 최소 44×44px이다.
- 기업 탭, 기간 선택, 카드 편집, 근거 보기, 다이얼로그를 키보드만으로 사용할 수 있어야 한다.
- 상태를 색상만으로 전달하지 않고 라벨, 아이콘 또는 설명을 병행한다.
- 차트는 시각 그래프 외에 동일 데이터를 읽을 수 있는 구조와 evidence 진입 경로를 제공해야 한다.
- 375px, 768px, 1280px에서 한국어·긴 기업명·긴 수치·전체 기간을 검증한다.
- `prefers-reduced-motion`을 존중하고 확대 시 주요 콘텐츠가 잘리거나 카드 내부 스크롤에 갇히지 않게 한다.

### 현재 열린 디자인 부채

아래 항목은 승인된 부채가 아니며, 해당 기능을 완료하기 전에 해결하거나 사용자 승인을 받아야 한다.

| ID | 위치 | 심각도 | 영향 사용자 | 문제 | 종료 조건 | 상태 |
|---|---|---|---|---|---|---|
| `DS-001` | `app.css`, `playground.css` | 보통 | 유지보수자, 모든 사용자 | 의미가 같은 원시 색상이 여러 위치에 반복된다. | 전역 재설계와 분리된 승인 작업에서 의미 토큰으로 통합 | 열림 |
| `A11Y-001` | Playground 모바일 컨트롤 | 보통 | 터치·운동 제약 사용자 | 일부 기존 모바일 컨트롤이 44px보다 작다. | 해당 화면의 터치 목표 수동 QA와 크기 보정 | 열림 |

### 승인된 접근성 부채

현재 사용자가 승인한 접근성 부채는 없다.

## 변경 절차

1. 새 디자인 역할이 필요하면 이 문서에 먼저 기록한다.
2. 기존 토큰으로 표현할 수 없을 때만 새 CSS 변수를 추가한다.
3. 재사용 컴포넌트의 구조·상태·접근성 계약을 먼저 갱신한다.
4. 구현 후 mobile 375px, tablet 768px, desktop 1280px에서 실제 화면과 상호작용을 검증한다.
5. 해결되지 않은 접근성·디자인 문제는 위치, 영향 사용자, 해결 조건과 함께 부채 표에 남긴다.
